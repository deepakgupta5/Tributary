# Codex storage boundary inspection

Inspected 2026-11-03 America/Vancouver. This is a path/configuration inventory, not a content audit or deletion certificate. No article text or nonprofit evidence was inserted to test persistence. No Codex setting was changed. The owner states this project is noncommercial research and requires copying/retention of selected permitted material.

| Surface | Observed or documented persistence path | Implication for the proposed trial |
| --- | --- | --- |
| Retrieved web content and tool output | This inspection's browser/search responses are displayed in the active chat. [Official Codex documentation](https://learn.chatgpt.com/docs/projects) says chats keep transcripts and recorded working directories. [OpenAI Work FAQ](https://learn.chatgpt.com/docs/enterprise/work-admin-faq) notes that Codex chats can create command output, diffs and logs. Exact hosted retention for this account was not established. | Treat anything printed to a tool result or chat as potentially retained in the session. Keep full live documents and large copied passages out of prompts and shell output. |
| Local Codex sessions | `~/.codex/sessions` exists (127 MB at inspection). `~/.codex/session_index.jsonl`, `thread_history_1.sqlite`, `logs_2.sqlite` and their WAL/SHM files exist. Contents were not opened. [Official advanced configuration](https://learn.chatgpt.com/docs/config-file/config-advanced) describes local session transcript persistence under `CODEX_HOME` by default; this installation may use additional desktop stores. | A selected excerpt placed in a review packet or tool result can survive local process exit. Do not assume transient processing only because a script deletes its input file. |
| Desktop app storage and caches | `~/Library/Application Support/Codex` exists (475 MB), including `Session Storage`, `Local Storage`, `Cache`, `blob_storage`, `artifact-sessions`, `sentry/queue` and `Crashpad`; `~/Library/Caches/com.openai.codex` exists (1.1 MB). Contents were not examined. | App/browser caches and diagnostic queues are possible persistence surfaces. Their exact retention and content for this task are unverified; deleting a trial temp file would not prove these copies absent. |
| Temporary files and shell logs | The prior synthetic run used a separate `/private/tmp/tributary-synthetic-v1` checkout and `/private/tmp` test output. No live source file was written for this inspection. Shell redirection, process logs, downloads and PDF processing can create additional copies. | A future collector should keep raw responses in memory when feasible, use an isolated temp directory only when needed, avoid response bodies in logs, and record post-run cleanup. Crash or tool caches can outlive normal cleanup. |
| Review packets, SQLite and exports | Current [`Store.review`](../../tributary/core.py) saves exact packet JSON in SQLite, including subject and transitive dependency bodies. [`report.export`](../../tributary/report.py) serializes reviews and records into JSON, JSONL and Markdown. The prior synthetic run's `out/` database is ignored by Git; committed `OutBound/evidence/evaluations/session-001` files are synthetic. | A permitted live excerpt could be copied into every downstream packet and export. Retention permission must cover these immutable/versioned copies and any hosted session processing. A whole live document must never enter a record body merely to make review convenient. |
| Git and remote repository | `git add`, commits and pushes preserve tracked bytes in history and GitHub. The repository's `.gitignore` excludes `out/` and SQLite files, but arbitrary new report or text files could still be tracked. | Keep live source text and private working data outside this public repository. A `.gitignore` entry alone is not a permission or privacy boundary. |
| Backups and synchronization | `tmutil destinationinfo` reported no configured Time Machine destination at inspection. Other backup/sync services and hosted service backups were not audited. [Official Work FAQ](https://learn.chatgpt.com/docs/enterprise/work-admin-faq) says retention differs across conversations, files, memories, apps and connected systems. | Do not claim all copies can be deleted or that no backups exist. A chosen private data location needs an explicit backup/sync decision before live retention. |

**Boundary conclusion:** The current coding-session environment cannot promise that a copied passage will be transient once it appears in a prompt, tool result or exact review packet. For the proposed trial, persist only source material whose handling basis covers the intended copies and session processing; otherwise use factual notes and links, leave exact-quote checks unresolved, or obtain a different documented basis. A source's public readability is separate from its permitted retained content. Official documentation and local paths establish possible storage locations; they do not establish that a particular live page was copied into each location.
