# Desktop source review before owner publication

Use the existing included desktop assistant. Do not call a paid model API, buy source access, bypass robots or access restrictions, or send outreach.

For each nonempty packet run four separate checkpoints, in order: `qc`, `researcher`, `skeptic`, `fact_checker`. QC receives the collector packet and checks identity, provenance and completeness as a separate responsibility. The researcher records what each original establishes. The skeptic reads that result and challenges scope, recency and alternative explanations. The fact-checker reads the original and the preceding results and checks all claims and the final disposition. Record the actual actor and context. Mark a material unresolved requirement `hold`.

For each stage write its own responses file keyed by signal ID, with `actor`, `result` (pass/hold), and `reason`. Run `python3 -m tributary.checkpoint_audit STAGE PACKET RESPONSES out/daily/latest/checkpoints/PACKET_ID`, substituting the actual stage, paths and packet ID. Inspect each execution before doing the next. For the fourth execution also pass `--verdicts out/daily/latest/desktop-verdicts.json`. Completion below requires the exact linked chain. An empty repeat needs no new executions. Previous unchained decisions must be rechecked before promotion.

1. In the operating checkout run `python3 scripts/run_daily.py --scheduled`. For a manual proof omit `--scheduled`. Collection and review preparation use saved source checkpoints. A skipped collection still permits finishing an existing pending review packet in `out/daily/latest`.
2. Read `out/daily/latest/source-review-request.json`. Each group is one account and original document, with separate flags. Python retrieves each original once per run, sharing responses with collection; unchanged source versions reuse recorded verdicts. Never review each flag with a separate network request.
3. If no flags need review, report reused verdicts with their original dates and skip completion. For groups needing review, read their `original_cache` JSON if available. This per-run temporary cache contains the parsed original and exact paragraph locators, hashes, publication metadata and source URL only while the producing command is running. It is deleted on normal exit and Python exception unwinding, including failed or unfinished reviews. A later desktop pass must re-fetch the permitted original once per account/document; do not recreate a persistent cache. Recheck the document version and locators before reusing a packet; a changed original requires fresh preparation. Read the whole relevant original, not just keyword snippets. If the cache is unavailable, use one permitted original retrieval for the group and reconcile the exact locator hashes. If neither is possible, leave the group unfinished. Do not attest to reading inaccessible material.
4. Check each claim separately. Record the exact attributed observation, source paragraph locator/hash, event/reporting period, comparison denominator, contradictory evidence, alternative explanations and current-status limits. An undated request for donations is not financial-pressure evidence. A successful campaign can support performance without difficulty. Do not equate volunteer inquiries with staffed capacity, percentage increases with dollar gaps, or forecasts with later outcomes.
5. Make researcher, skeptic and fact-checker passes in the included desktop session. Record that shared context honestly; these are not independent reviewers. Keep the factual verdict separate from the flag interpretation and Autonomy Bridge relevance. Owner escalation requires supported current evidence, completed source checks, an explicit commercial decision and one owner next step. Missing dates, inaccessible sources and unfinished research stay internal.
6. Write `out/daily/latest/desktop-verdicts.json` with `contract: source-review-v1`, the exact request `packet_id`, `reviewed_at`, and one verdict per requested flag. See the first live batch's [validated example](../evidence/day-6/source-review/desktop-verdicts.json). Required fields and allowed values are enforced by `tributary.source_review.validate`. Evidence references must use the request's exact locator/hash. Explicitly use `research_required` for unresolved source questions; never manufacture completion to fill a schema. A batch can contain only research dispositions and produce zero owner cards.
7. Run `python3 -m tributary.source_review complete --verdicts out/daily/latest/desktop-verdicts.json`. Python atomically validates the entire batch against current candidate/document versions, records verdict history and publishes the gated owner view. A changed relevant or cited passage reopens that claim. A changed comparison/counterevidence passage can affect multiple claims. Harmless unrelated edits preserve decisions. Never change the private feedback journal to make a repeat pass.
8. If review cannot finish or validation fails, run `python3 -m tributary.source_review publish`. Report collection status, unfinished research count, and the last reviewed worklist with its original dates. Never label this fallback freshly verified. Do not delete or replace the last successful review with an empty unreviewed snapshot.
9. Return the local owner-worklist path and counts for new accounts, new/changed candidates, owner attention and outstanding research. Distinguish manual execution from a later scheduler execution. Do not commit, push, merge or contact anyone from the unattended job.

Default publication is `out/daily/latest/worklist.md`. Raw collection is diagnostic `collection-worklist.json`, not an owner queue. `research-queue.json` includes closed unsupported flags and unfinished source questions. Private decisions remain in the existing append-only SQLite journal, bound to reviewed evidence fingerprints. Full parsed originals never persist in the state directory. Their per-run temporary directory is removed at command exit; permitted hashes, metadata and bounded excerpts remain. Cleanup runs on exceptions too, but power loss or an uncatchable process kill cannot guarantee immediate OS-temp cleanup. Legacy full-original files written by this application are removed from the state-dir source-cache on the next invocation, without touching feedback or unrelated files.
